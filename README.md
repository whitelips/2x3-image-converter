# 2:3 이미지 변환기

이미지를 자르거나 늘리지 않고, 검은 여백을 더해 가로:세로 **2:3**으로 맞추는 브라우저 도구입니다.

**[변환기 열기](https://whitelips.github.io/2x3-image-converter/)**

## 사용 방법

1. 이미지 파일을 여러 개 선택하거나 드래그 앤 드롭합니다. 이미지 URL도 줄바꿈 또는 공백으로 구분해 여러 개 입력할 수 있습니다.
2. **2:3으로 변환**을 누릅니다. 파일과 URL을 섞어서 처리할 수 있습니다.
3. 기본 설정에서는 완료 후 자동 다운로드합니다. 한 장은 이미지 파일로, 여러 장은 ZIP으로 저장합니다. 자동 저장을 브라우저가 차단하면 전체 다운로드 또는 각 항목의 저장 버튼을 누릅니다.

실패한 항목은 개별 오류를 표시하며, 나머지 이미지는 계속 처리합니다. 실패 항목 재시도, 변환 중지, 개별 삭제와 전체 초기화를 지원합니다.

## 변환 규칙

- 원본 표시 크기를 유지하고 중앙에 배치합니다. `k = max(ceil(가로 / 2), ceil(세로 / 3))`으로 계산한 `2k × 3k` 캔버스에 검은색 여백을 더합니다. 홀수 여백은 오른쪽·아래쪽에 1px 더 배치합니다.
- 이미 2:3인 이미지는 재인코딩하지 않고 원본 바이트를 그대로 저장합니다.
- 원본 형식을 유지합니다: WebP → WebP, PNG → PNG, JPEG → JPEG. `.jpg`와 `.jpeg` 확장자도 유지합니다. 형식은 확장자가 아닌 파일 내용을 검사합니다.
- WebP는 libwebp WebAssembly 인코더의 `lossless: 1`, `near_lossless: 100`, `exact: 1`로 저장합니다. PNG도 무손실로 인코딩합니다. **JPEG는 브라우저 최고 품질로 재인코딩하며 손실이 발생할 수 있습니다.**
- 변환된 이미지는 브라우저가 디코딩한 sRGB 캔버스를 기준으로 저장합니다. 투명 영역은 검은색으로 합성합니다. EXIF 방향은 표시 방향에 반영하지만, 변환 결과에 EXIF·ICC 등 원본 메타데이터를 복사하지 않습니다. 고비트 심도·광색역 원본까지 파일 수준으로 보존하는 도구는 아닙니다.
- 같은 이름의 파일은 `_2x3_2`, `_2x3_3` 등을 붙여 ZIP 내부 덮어쓰기를 방지합니다.

## 지원 범위

정지 WebP, PNG, JPEG만 지원합니다. 움직이는 WebP·PNG는 첫 프레임으로 조용히 바꾸지 않고 안내 메시지로 거부합니다. 파일 수·파일당 용량·전체 용량·픽셀 수·변 길이에 애플리케이션이 정한 상한은 없습니다. WebP 인코딩에도 고정 시간 제한을 두지 않으며 사용자가 중지할 수 있습니다.

실제 처리 범위는 브라우저의 캔버스·메모리와 인코더에 따라 달라집니다. 예를 들어 6,000 × 9,000 이미지는 RGBA 버퍼 하나에 약 216 MB가 필요하고, 디코딩·인코딩 과정에서는 추가 메모리를 사용합니다. 한 장씩 처리하며 디코딩한 원본과 캔버스는 사용 후 바로 해제하지만, 큰 이미지나 대량 ZIP 생성은 느려지거나 메모리 부족으로 탭이 종료될 수 있습니다. 탭 자체가 종료되면 웹페이지에서 오류를 표시할 수 없습니다.

WebP 변환 결과는 [형식 자체의 최대 변 길이 16,383px](https://developers.google.com/speed/webp/faq#what_is_the_maximum_size_a_webp_image_can_be)을 지켜야 합니다. 이 한도를 넘으면 별도 안내하며, 크기를 줄이거나 다른 형식으로 몰래 바꾸지 않습니다. 이미 2:3인 파일은 기존처럼 원본 바이트를 유지합니다. 캔버스 할당·인코딩 실패는 해당 항목에 표시하고 나머지 처리를 이어갑니다. 대량 처리에서 ZIP 준비가 실패하더라도 완료된 파일은 개별 저장할 수 있습니다.

URL은 이미지 파일을 직접 반환해야 합니다. **Mnet Plus CDN(`https://image.cdn.mnetplus.world`) URL은 전용 Cloudflare Worker로 자동 중계**합니다. 여러 URL을 한 번에 입력하면 원본 수신 → 브라우저에서 2:3 변환 → ZIP 자동 다운로드까지 이어집니다. 터미널 실행, 원본 개별 저장, 재첨부가 필요하지 않습니다.

중계 주소는 `https://2x3-image-relay.whitelips19.workers.dev/`입니다. [Worker 코드와 배포 안내](relay/README.md)를 참고하세요. Cloudflare Worker 배포는 GitHub Pages 배포와 별개입니다.

다른 도메인은 브라우저에서 직접 읽으며, 서버의 CORS 허용이 필요합니다. 로그인이 필요한 URL은 지원하지 않습니다. 원본을 읽지 못한 경우 나머지 항목은 계속 처리하고 실패 항목은 재시도할 수 있습니다. 직접 접근이 차단된 항목은 **파일 첨부 필요** 상태로 유지합니다. 원본 파일 여러 개를 한 번에 첨부하면 이름이 같은 URL에 연결해 변환을 이어갑니다. 이름이 다르거나 같은 파일명의 URL이 여러 개이면 사용자가 연결할 원본을 선택합니다. 선택적 원본 미리보기는 제공하지만 새 창을 자동으로 열지 않습니다.

URL 읽기 요청은 쿠키와 Referer 없이 전송하며 서버의 최초 응답에만 30초 제한을 둡니다. 응답이 시작된 뒤 큰 파일을 받는 시간은 제한하지 않으며 중지 버튼으로 취소할 수 있습니다. 원본 미리보기는 Referer 없이 해당 원본 서버에 요청하며 브라우저의 일반 이미지·쿠키 정책이 적용됩니다.

첨부한 파일은 서버에 업로드하지 않습니다. CDN URL과 이미지 바이트는 사용자가 관리하는 Cloudflare Worker를 통과하지만 변환과 ZIP 생성은 브라우저에서 실행합니다. Worker는 허용된 CDN만 요청하며 이미지·URL을 앱 로그·저장소·캐시에 남기지 않도록 구성합니다. Workers Logs·Traces·Worker Cache 설정도 꺼야 합니다. Cloudflare 자체의 운영·보안용 정보 처리까지 없애거나 유출 가능성 0을 보장하는 구조는 아닙니다. 분석 스크립트나 로컬 스토리지를 사용하지 않으며 새로고침하면 목록과 변환 결과가 사라집니다.

## 로컬 개발

Node.js 24 기준입니다.

```sh
npm ci
npm run dev
```

개발 주소: `http://127.0.0.1:5173/2x3-image-converter/`

```sh
npm test
npx playwright install chromium webkit
npm run test:e2e
npm run build
```

Vite + 기본 HTML/CSS/JavaScript를 사용합니다. WebP 인코딩은 Web Worker에서 실행하고, ZIP은 fflate로 생성합니다. 런타임 의존성 및 코덱 라이선스는 [THIRD_PARTY_NOTICES.txt](public/THIRD_PARTY_NOTICES.txt)에 포함합니다.

테스트는 중계의 허용 도메인·리다이렉트·CORS·헤더·바이트 보존, 캔버스 계산·입력 검증과 Chromium/WebKit에서의 다운로드·형식 유지·무손실 픽셀 비교·여러 URL 중계·부분 실패 및 재시도·중지·모바일 폭을 검사합니다. WebKit의 iPhone 뷰포트 테스트는 실제 iPhone 테스트를 대체하지 않습니다.

## GitHub Pages 배포

저장소의 **Settings → Pages → Source**를 **GitHub Actions**로 설정합니다. `main`에 push하면 `.github/workflows/pages.yml`에서 단위 테스트, Chromium/WebKit 브라우저 테스트와 프로덕션 빌드를 실행한 뒤 `dist/`를 배포합니다. Pull request는 검증만 실행합니다.

프로젝트 경로는 `vite.config.js`의 `base: '/2x3-image-converter/'`로 설정되어 있습니다. 저장소 이름을 변경하면 이 경로도 변경해야 합니다.
